# Databricks migration (Talend + SQL Server → Databricks)

This directory holds the Databricks port of the banking DWH: a Databricks Asset Bundle
(`databricks.yml`), PySpark notebooks, Spark SQL, and local tests. Ticket PRs build on
this scaffold. **Every ticket must follow the conventions below.** If a ticket needs to
change one, say so in the PR description instead of changing it quietly.

## Conventions (contract for all tickets)

### Unity Catalog layout
| Item | Name |
|---|---|
| Catalog | `banking_etl_dev` (dev), `banking_etl_prod` (prod). Bundle var `catalog`. |
| Schemas | `bronze`, `silver`, `gold`, `ops` (audit, DQ results, reconciliation, rejects, checkpoints). Bundle var `schema_prefix` is prepended (empty by default; `banking_etl_` when sharing the `migration_demo` catalog). |
| Landing volume | `<catalog>.bronze.landing` → `/Volumes/<catalog>/bronze/landing/transactions/{csv,excel}/` and `/sample_db/<table>/` (fixture mode). |
| Checkpoints / schema locations | `<catalog>.ops.checkpoints` volume. |
| Secret scope | `banking-etl-sqlserver`, keys `jdbc-host`, `jdbc-port`, `jdbc-database`, `jdbc-user`, `jdbc-password`. |

Always resolve names through `banking_etl.config.Settings` (`table()`, `landing_path()`, `checkpoint_path()`). Never hard-code catalog or schema names.

### Tables per layer
- **bronze**: raw, source-shaped, snake_case source column names, plus `_ingested_at TIMESTAMP` and `_source STRING` (and `_source_file`, `_rescued_data` for files).
  - `bronze.sqlserver_{customer,city,state,account,branch,transaction_db}`: full snapshot per run (overwrite; Delta time travel keeps history). This mirrors Talend's full extracts.
  - `bronze.file_transaction_csv`, `bronze.file_transaction_excel`: Auto Loader / incremental append.
- **silver**: typed, cleansed, conformed, snake_case: `silver.branch`, `silver.account`, `silver.customer` (customer ⨝ city ⨝ state, uppercase cleansing per the Talend tMap), `silver.transaction` (union of the 3 sources, deduped on `transaction_id`).
- **gold**: star schema with **legacy column names (PascalCase) kept for reconciliation parity with `sql_scripts/01_create_tables.sql`**: `gold.dim_branch`, `gold.dim_account`, `gold.dim_customer`, `gold.fact_transaction`.

### Types
`MONEY → DECIMAL(19,4)`, `DATETIME/DATETIME2 → TIMESTAMP`, `DATE → DATE`, `INT → INT`, `VARCHAR(n) → STRING`. Source `customer.age` is `varchar(3)` → cast to `INT` in silver.

### Keys and constraints (Delta)
- Natural keys keep their legacy names (`AccountID`, `BranchID`, `CustomerID`, `TransactionID`) and are declared `NOT NULL` + informational `PRIMARY KEY` (UC PK/FK are not enforced).
- Each dim also gets a surrogate key `<Entity>Key BIGINT GENERATED BY DEFAULT AS IDENTITY` (`BranchKey`, `AccountKey`, `CustomerKey`).
- `fact_transaction` carries the legacy natural keys plus `AccountKey` and `BranchKey` from dimension lookups, with informational `FOREIGN KEY`s on the natural keys.
- Delta doesn't enforce FKs, so referential integrity is enforced in code. Fact rows whose `AccountID`/`BranchID` have no dim match go to `ops.fact_transaction_rejects`, matching SQL Server, where the FK would have rejected them.

### Load semantics (from the Talend jobs)
- Dims: Talend `CREATE_IF_NOT_EXISTS` + `INSERT`. Ported as **SCD-1**: `MERGE` on the natural key (update changed attributes, insert new, no hard deletes). Surrogate keys are stable across runs.
- Fact: Talend `TRUNCATE` + `INSERT`. Ported as a **full refresh** of `gold.fact_transaction` (`INSERT OVERWRITE` / `replaceWhere`-free overwrite).
- Dimension load order: `dim_branch → dim_account → dim_customer → fact_transaction`.

### Code layout
- `src/banking_etl/<area>/...py`: pure PySpark functions (DataFrame in → DataFrame out, or `load_*(spark, settings)`), unit-tested locally.
- `notebooks/<layer>/<name>.py`: thin Databricks source-format notebooks (`# Databricks notebook source`) that add `../../src` to `sys.path`, build `Settings` via `settings_from_widgets(dbutils)`, and call `src` functions.
- `sql/<area>/*.sql`: Spark SQL DDL/views, parameterised with `${catalog}`/`${schema_prefix}`-style substitution or `IDENTIFIER(:catalog || ...)`.
- `resources/<ticket-slug>.yml`: bundle resources owned by one ticket. **Never edit `databricks.yml` or another ticket's resource file**; the orchestration ticket (10) owns the end-to-end job.
- `tests/<area>/test_*.py`: pytest with the local Spark + Delta session in `tests/conftest.py`.
- `docs/<ticket-slug>.md`: optional per-ticket notes (mapping decisions, parity evidence).

### Local development
```bash
cd databricks
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt   # pyspark 4.0 + delta-spark 4.0 (DBR 17.3 LTS)
pytest
databricks bundle validate -t dev      # needs DATABRICKS_HOST + auth
```
Spark 4.0 needs **Java 17+** (`export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64` on Devin VMs). Jars resolve through the GCS Maven mirror (override with `SPARK_JARS_REPOSITORIES`) because Maven Central returns 429s.

### Source data
- `fixtures/sample_db/*.csv`: exports of every source table in `data_sources/sample.bak` (restored on SQL Server 2022): customer(20), city(52), state(9), account(21), branch(5), transaction_db(10).
- `../data_sources/transaction_csv.csv` (12 rows, `dd-MM-yyyy HH:mm:ss`) and `../data_sources/transaction_excel.xlsx` (Sheet1, 7 rows).
- To test the JDBC path locally, restore `sample.bak` into `mcr.microsoft.com/mssql/server:2022-latest` (logical files `sample` / `sample_log`) and set `SPARK_EXTRA_PACKAGES=com.microsoft.sqlserver:mssql-jdbc:12.8.1.jre11`.
